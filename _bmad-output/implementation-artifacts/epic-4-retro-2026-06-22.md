## 3. Team Discussion — What to Improve & Patched Issues

### 🔴 Issue 1: RPCError Instantiation Error — FIXED during Story 4.4
**Problem:** In `delivery.py`, `RPCError` was instantiated incorrectly, which caused the delivery retry loop to fail when catching certain API errors.
**Fix:** Corrected the parameter schema for `RPCError` in the catch-block.

### 🔴 Issue 2: TypeError during Entity Casting — FIXED during Story 4.4
**Problem:** Passing a string channel ID like `"-10012345"` to Telethon caused a type error since the client expects an integer.
**Fix:** Cast all string-formatted numeric IDs to `int` before passing them to Telethon.

### 🔴 Issue 3: Pipeline Isolation Bypassed in DeliverStep — FIXED during Story 4.4
**Problem:** Exceptions raised during delivery bypassed the isolated `PipelineEngine.execute` catch-block, meaning a single rule failure could potentially crash the worker.
**Fix:** Ensured all exceptions are caught and wrapped inside `DeliverStep.apply()` to comply with the per-rule failure isolation requirement (AC 4).

### 🔴 Issue 4: FloodWait Cap Propagated Exception Blindly — FIXED during Story 4.4
**Problem:** When a `FloodWait` exceeded the 300-second maximum threshold, the exception was propagated directly, causing the task to crash.
**Fix:** Modified the cap handler to abort the pipeline run gracefully by returning a `BlockedOutcome(reason="flood_wait_exceeded")`.

### 🔴 Issue 5: Concurrent Context Leakage — FIXED during Story 4.5
**Problem:** Sequential execution of rules on the same event leaked context variables across pipelines.
**Fix:** Wrapped concurrent executions in `copy_context().run()` to ensure strict contextvar isolation.

## 6. Pre-Start Notes for Epic 5

These notes are for the development team before starting Epic 5:

### 1. Ingesting Edit and Delete Events
Epic 5 requires the worker to handle `events.MessageEdited` and `events.MessageDeleted`. Remember that deleted messages do not have their full text content; lookups must be performed strictly using `(source_channel_id, source_message_id)` in the `message_mappings` collection to identify the corresponding destination message.

### 2. Lifespan Task Cleanup
The mapping sweeper must run hourly using a background coroutine in the lifespan. Ensure it utilizes the `forwarded_at` compound index to delete expired mappings without performing slow full-table scans.

### 3. Log Redaction Check
Ensure all log entries are passed through the `SecretRedactor` to clean out session bytes and API keys. We must make sure this does not redact ordinary data.
