## Challenges & Growth Areas

### 1. Epic-Level Status Drift in sprint-status.yaml (**Fixed in this retro**)

All three stories were marked `done`, but `epic-2: in-progress` was never promoted to `done`. This is the second occurrence of this pattern (Story 1.3's frontmatter in Epic 1). The YAML is the authoritative tracking artifact — drift here causes misleading sprint summaries.

**Root cause:** No explicit step in the story-close workflow to promote epic-level status when the last story in an epic closes.

**Fixed:** `epic-2: done`, summary counts corrected, `last_updated` refreshed (2026-06-17).

### 2. Review Records Missing for Stories 2.2 and 2.3

Story 2.1 has a `### Review Findings` section. Stories 2.2 and 2.3 do not. It is unclear whether:
- Reviews were conducted but findings not documented, or
- Reviews were skipped on the strength of passing tests

Given 17 findings were caught in Epic 1's review process (including a dead `lifespan` function that would have been a production bug), maintaining structured review discipline matters for Epic 3+ which has substantially more complex logic.

**Root cause:** No enforcement mechanism — review section in story template is optional.

### 3. Motor Aggregate Cursor: sync vs. async Gotcha

Story 2.3's debug log records:
> "Fixed aggregate pipeline unit test mock: `collection.aggregate` returns cursor synchronously in Motor, so we replaced `AsyncMock` return value with `MagicMock`."

This is a non-obvious Motor behavior. `collection.aggregate()` in Motor returns a synchronous `AsyncIOMotorCommandCursor` — you `await` the iteration, not the call itself. This pattern will recur in every story that mocks aggregation pipelines (Epic 3's cache, Epic 4's pipeline metrics, Epic 5's stats API).

**Root cause:** Motor's sync-call-async-iterate pattern is not documented in the test guidelines.

### 4. PATCH Username Normalization — Potential Repeat of Story 2.1 Bug

Story 2.1's sole patch finding was empty `telegram_username: ""` slipping through the sparse unique index.
Story 2.2's PATCH endpoint also normalizes `telegram_username` (strip `@`, check uniqueness). If `""` can reach this path after normalization, the same `DuplicateKeyError` may surface on PATCH. This was not explicitly tested.

**Root cause:** Bug fix in Story 2.1 didn't trigger a regression test on the equivalent PATCH path in Story 2.2.

### 5. settings.py / config.py Naming Duplication (**Resolved in this retro**)

This was a Medium-priority technical debt item from Epic 1 targeted for Story 2.1 as an opportunistic refactor. It was not resolved during the epic. On investigation:
- `settings.py` was a deprecation shim re-exporting from `config.py`
- No code in the project imported from `settings.py`
- The shim was dead weight

**Resolved:** `settings.py` deleted (2026-06-17). `config.py` is now the single source of truth.

## Key Insights & Learnings

1. **Retro action items work when they have owners and are pre-loaded into story specs.** The deferred-work.md entries for Epic 2 were specific, owned, and acted on. The action items that weren't pre-loaded (settings.py refactor) drifted.

2. **The quality bar from Epic 1's code review process carried forward in architecture, not in process.** The Clean Architecture patterns set in Epic 1 constrained implementation choices positively (fewer places to introduce bugs). But the review discipline itself wasn't enforced — 2 of 3 stories have no review record.

3. **Aggregate pipeline mocking needs a standard.** The Motor sync/async cursor distinction will surprise every dev agent that hasn't seen it. A documented pattern is worth 10 debug cycles.

4. **Epic status promotion is a workflow gap.** Individual story status is tracked correctly. Epic-level status is manually managed and was missed. This gap will compound as more epics complete.

5. **Test-driven development at the story level is working.** 86 net new tests in one epic, all green at close. The `BaseRepository` pattern created naturally testable code units.
