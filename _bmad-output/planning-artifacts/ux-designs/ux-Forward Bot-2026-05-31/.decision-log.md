## 2026-05-31 — PRD extract: settled decisions inherited from product

- **Product:** Self-hosted Telegram automation service (Telethon MTProto worker) controlled by a web admin dashboard + REST API. Despite the name, NOT a chat bot — it's a background worker plus operator UI.
- **Persona (sole):** Channel Operator — single human running one instance. Comfortable with REST/Docker OR dashboard-only. Owns the Telegram user account.
- **Form-factor:** Desktop-first web app. Dashboard served by FastAPI at `/`, API at `/api/v1/*`. Mobile responsive **out of scope** beyond "doesn't break at narrow widths" (addendum.md:366).
- **UI system:** **shadcn/ui** on React 18 + TypeScript + Vite + Tailwind + TanStack Query + React Router (prd.md:465). Both spines inherit from shadcn/ui defaults.
- **Aesthetic directive:** "Pragmatic, not glossy. Functional internal-tool aesthetic. shadcn/ui defaults are fine." (addendum.md:286)
- **Stakes:** Internal operator tool. Not consumer-facing. Auth = single `X-API-Key` → HttpOnly session cookie.
- **Out of scope for MVP UI:** Accessibility commitments, i18n, theme switching, offline. (addendum.md:362–369)
- **IA pre-set in addendum §9.3:** 8 surfaces — S1 Dashboard, S2 Forwards List, S3 Forward Create/Edit, S4 Sources List, S5 Source Create/Edit, S6 Folder Modals, S7 Logs, S8 Settings + Login.
- **Positioning:** Competitive with Junction Bot (`junctionbot.io`); pitched against tariffed/closed services.
- **Production posture:** "MVP is no longer 'minimal'; it is **production-grade with a competitive feature surface and an operator dashboard**." (prd.md:20)

## 2026-05-31 — Discovery round 1: foundation choices

- **Audience:** Single operator — you, personal tool. Implication: optimize for raw operator efficiency over polish, onboarding warmth, or self-explanatory copy. Empty states can assume "I built this and I know what to do."
- **Density:** shadcn default ("comfortable"). Implication: stock spacing tokens, no override of `--spacing`.
- **Color personality:** Tinted neutral with a single accent. Accent color TBD (see Discovery round 2).
- **Dark mode:** Both — system-follow toggle in Settings. **⚠ Delta from PRD:** addendum.md:362–369 lists theme switching as out of scope for MVP UI. This decision overrides that. Tokens must define `colors.light.*` and `colors.dark.*` from Discovery onward.

## 2026-05-31 — Discovery round 2: visual flavor + behavioral anchors

- **Accent color: Forwarding Green** (light `#16A34A` / dark `#22C55E`) on warm stone neutral. Source: `.working/color-themes-1.html` variation 2. Register: "active pipeline / signal flowing."
  - Watch-out (captured for finalize): green-as-accent and green-as-success-state risk collapsing into one signal. EXPERIENCE.md must separate the two — e.g., accent green for primary actions + toggle ON; success-emerald-tinted for state pills, with shape/icon to disambiguate.
- **Session shape:** Weekly 15–30 min config sessions. Implication: optimize Forwards List efficiency, S3 form ergonomics, and bulk operations over dashboard glance-ability.
- **Log severity language:** Color tier + icon + bold label. Severity carries primary meaning; icons are redundant for accessibility floor. Decided mapping (initial):
  - `forwarded` → success green, ↗ icon
  - `outside_time_window` / `sampled_out` / `blocked_keyword` / `media_type_filtered` → muted gray, ⊘ icon, "Filter-blocked"
  - `telegram_rejected` → error red, ⚠ icon
  - `destination_unreachable` → error red, ⛔ icon, distinct from telegram_rejected
- **First-run:** Guided wizard modal on first login. Steps: (1) Telegram connection check → (2) register first source → (3) create first forward. Skippable. **⚠ Slight delta from PRD:** addendum.md:438 frames first-run as "open dashboard, register a source, create a rule" without naming a wizard. This decision *implements* that vision via a guided overlay rather than relying on empty-state hints alone.

## 2026-05-31 — Discovery round 3: form behavior + voice

- **S3 collapsible panels:** All collapsed by default; expand to edit. Implication: panel headers must surface enough summary state (e.g., "Filters — 3 keywords, time-window active") so the operator doesn't have to expand to see what's there.
- **Validation error voice:** Terse + technical. No apology, no warmth. Pattern: `<field>: <reason>`. Examples: "Invalid regex: unclosed group at col 14." "Time window: end < start." "Duplicate rule for source 1234." Surfaced inline next to the offending input. **Sets the voice for the whole product** — empty states and toasts inherit this register.
- **New rule default state: inactive.** Resolves PRD OQ-RuleActiveDefault. Operator creates, reviews, then flips on via the Activation panel toggle. Implication: S3 must make the "now flip it on" gesture obvious post-save — likely a prominent activation banner on the saved rule's edit page until first activation.
- **Bulk enable/disable feedback:** Progress-bar toast during dispatch ("Enabling 23 of 47 forwards…"), summary toast at end ("Done. 45 enabled, 2 failed. [Show errors]"). Errors expand inline in a follow-up surface. Toast persists until dismissed when failures exist.

## 2026-05-31 — Discovery round 4: degraded modes + tactical patterns

- **Telegram-disconnected degraded mode:** Global red banner at top of every screen ("Telegram disconnected — [Reconnect]"). Forwarding write actions (toggle on, save rule, save source) disabled until reconnect; read views (Logs, list views, Settings) remain accessible. Implication: tokens need a `state.degraded` color (a distinct red tone from `error`) and disabled-button treatments must remain readable.
- **File picker (media replacement):** Upload-or-pick combo. Drag-drop a new file into `MEDIA_REPLACEMENT_BASE_DIR` OR pick from existing files. Implies a small file-upload flow with server-side path-containment validation. **⚠ Implementation cost flag:** this is the heaviest of the three options; the operator-tool stakes may not warrant it. Verify at Finalize.
- **Filter summary icons (S2 Forwards List):** Tiny lucide icons, one per filter type:
  - Time-window → `clock`
  - Sampling → `shuffle`
  - Media-type → `image` (or `film` if mixed)
  - Keyword (block/allow) → `key` or `filter-x`/`filter-check`
  - Inactive filter → 40% opacity, no tint. Active → full opacity, accent tint.
  - Hover: tooltip with the active config (e.g., "Mon–Fri 09:00–17:00 Europe/Warsaw").

## 2026-05-31 — Finalize triage decisions

- **File picker (S3 Media Replacement) — downgraded to dropdown-only.** The earlier "upload-or-pick combo" added a `POST /api/v1/media/upload` endpoint the PRD never specified, plus path-containment / MIME / size validation. Personal-tool stakes don't warrant the extra surface. New pattern: shadcn `Combobox` listing existing files under `MEDIA_REPLACEMENT_BASE_DIR` (server provides `GET /api/v1/media/replacement-images` returning the directory listing — a read endpoint, not a write). Operator places files via SFTP / `docker cp` / bind-mount. Matches PRD FR-41 literal (prd.md:385: "the operator must ensure read access"). Both spines updated. The `[NOTE FOR UX]` in DESIGN.md Do's-and-Don'ts is removed (concern resolved).
- **Telegram-disconnected banner — narrowed to banner-only, no action disabling.** Earlier spine disabled all forwarding write actions during disconnect. New behavior: banner shows, **all actions stay enabled**. Operator decides what's safe. Power-user posture matches "just me, personal tool" framing. The implicit-contradiction concern from reconcile (over-broad write-disable) is resolved by removal. Banner copy unchanged: "Telegram disconnected — last event Nm ago — [Reconnect]". Banner still uses `role="alert"` + `aria-live="assertive"` so screen readers announce the condition.
